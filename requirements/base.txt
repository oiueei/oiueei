# Direct dependencies, pinned to exact versions.
#
# They used to be ranges (`Django>=5.0,<6.0`). A range is resolved at install
# time, so CI and the Heroku build could each pick a different version on the
# same commit — and the `pip-audit` run in .github/workflows/tests.yml would then
# be auditing something other than what production actually installs. A release
# published between the CI run and the deploy lands in production having been
# audited by nobody. Exact pins make the audit and the slug agree.
#
# **Transitive dependencies are still unpinned**, which is the remaining half of
# the job: a full lock (`pip-compile --generate-hashes`) has to be resolved
# against the interpreter that will run it — Python 3.12, per .python-version and
# the CI matrix — and resolving it on anything else can pin a version that has no
# 3.12 wheel or drop a backport guarded by a `python_version` marker. Generate it
# on a 3.12 environment when adding one.
#
# Bumping: change the version here, run the suite, and let `pip-audit` in CI
# confirm the new pin is clean. Dependabot opens these as ordinary PRs.
